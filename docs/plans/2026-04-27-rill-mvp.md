# Rill MVP Implementation Plan

> **For implementers:** Work through this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Rill V1 as a private, local-first feed reader for one user, with RSS/Atom/JSON Feed ingestion, Cloudflare D1 sync, offline cache, OPML, strict privacy defaults, and a calm Today/Reader loop.

**Architecture:** Rill is a TypeScript monorepo in one app. A Vite React PWA owns the local-first UI and IndexedDB cache. A Cloudflare Worker owns auth, feed fetch/discovery, D1 persistence, Cron refresh, Queue consumers, OPML, and the authenticated image proxy. Shared TypeScript modules define types, feed normalization, OPML parsing, sanitization policy, and state mutation contracts.

**Tech Stack:** TypeScript, Vite, React, Vitest, Playwright, Cloudflare Workers, Wrangler, D1, Queues, IndexedDB via `idb`, feed parsing via small XML/HTML parsers, DOMPurify-compatible sanitization, system fonts only.

## Per-Task Quality Gate

Every task ends with this gate before commit. Do not skip it.

1. **Documentation clarity:** Update nearby docs or comments only when they clarify durable behavior. Delete vague prose. Keep language direct and specific.
2. **Hygiene:** Run `git status --short`, remove scratch files, avoid orphaned artifacts, and keep generated or QA-only files out of git unless the plan explicitly says to keep them.
3. **Quality scan:** No em dashes, no placeholders, no vague labels, no ornamental copy, no fake data presented as real, no generic template prose. UI copy should sound like the product, not like a template.
4. **Senior-engineer code review:** Check boundaries, naming, types, error paths, dependency creep, privacy constraints, and whether the code can be changed later without untangling a blob. Refactor before committing if a file is doing too much.
5. **Verification:** Run the task-specific commands plus `npm run typecheck` when TypeScript changed. If UI changed, run `npm run build` and inspect the resulting surface before claiming done.
6. **Commit only clean work:** Commit only after the above gate passes. Mention any known limitation explicitly in the commit-adjacent notes or final status.

This gate is part of the implementation contract, not optional polish.

## Scope Check

The design spec covers a full MVP with frontend, backend, database, background refresh, offline behavior, and visual constraints. This plan keeps it as one implementation sequence because the pieces must work together for the manual acceptance scenario. The tasks are still sliced so each one produces verifiable software:

1. project skeleton and contracts
2. feed parsing fixtures
3. D1 schema and auth
4. add-source and discovery
5. Notebook visual integration from the Paper handoff
6. refresh jobs and dedupe
7. local-first client cache and sync queue
8. reading UI
9. sources and OPML
10. privacy/PWA hardening
11. end-to-end acceptance

Do not add generated summaries, recommendations, push notifications, full-text extraction, analytics, external fonts, third-party scripts, component libraries, or fake thumbnails.

Notebook is the active design direction. Treat the Paper PNG exports in `docs/design/reference/` as the visual spec for Today, Reader, Sources, and mobile Today. The early scaffold from Tasks 1-5 is allowed to be visually rough only until Task 5A. After Task 5A, new UI work must preserve the Notebook tokens and anatomy.

```ts
import type { Env } from './env';

const securityHeaders = {
  'content-security-policy': "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self'; font-src 'self'; frame-src 'none'; object-src 'none'; base-uri 'self'; form-action 'self'",
  'referrer-policy': 'no-referrer',
  'x-content-type-options': 'nosniff',
  'permissions-policy': 'camera=(), microphone=(), geolocation=()'
};

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);
    if (url.pathname === '/api/health') {
      return Response.json({ ok: true });
    }
    const asset = await env.ASSETS.fetch(request);
    const response = new Response(asset.body, asset);
    for (const [key, value] of Object.entries(securityHeaders)) response.headers.set(key, value);
    return response;
  },
  async scheduled(_event: ScheduledEvent, _env: Env): Promise<void> {},
  async queue(_batch: MessageBatch, _env: Env): Promise<void> {}
};
```
